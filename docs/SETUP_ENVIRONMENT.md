# 簡単起動と別端末への引き継ぎ

## 端末ごとの役割

| 端末 | 必要な準備 |
| --- | --- |
| ATEMにつながるWindows PC | LAN・IP設定、Node.js 20.19以上、Tailscale、プロジェクト一式、`start-atem.cmd` |
| 操作用のスマホ・別PC | Tailscale、ブラウザ、環境プロファイルの取り込み |

スマホにNode.jsやプロジェクト一式は不要です。ATEM制御はLAN経由で、USB映像取り込みとは別です。IP・サブネット・ルーター設定はこのツールでは変更しません。操作端末も同じtailnetに参加し、接続先PCへのアクセスが許可されている必要があります。

## Windowsの初回

1. GitHubから最新版を取得し、ZIPなら展開します。
2. Node.js 20.19以上とTailscaleを用意してログインします。
3. ATEM Setupで本体のIPを確認し、PCからLAN通信できるよう手動設定します。
4. `start-atem.cmd`をダブルクリックします。通常、管理者実行は不要です。
5. `/atem`が未設定の場合だけ、追加内容を確認して `y` と答えます。OBS用 `/` は変更しません。同じ設定があれば再利用し、競合やFunnelがあれば停止します。
6. ATEM本体のLAN IPv4アドレスを入力します。初回・依存関係更新時はインターネットから必要なものを準備します。
7. 専用キーが自動生成され、接続ガイドが開きます。「仲介の起動」と「ATEM接続成功」は別々に表示します。

以前の手動起動が動いている場合は、切り替えてよい時点でそのPowerShellを `Ctrl+C` で停止してから実行してください。8788番が使用中ならツールは何も停止せず案内して終了します。新ツールの初回は新キーになるため、操作端末にも登録し直します。

「表示」「コピー」でキーを確認できます。クリップボード履歴や端末間同期に残る可能性があるためコピー時は確認します。終了時は現在のクリップボードがそのキーと一致する場合だけクリアしますが、履歴の消去は保証しません。画面共有中の表示・撮影には注意してください。

## 毎回の起動・停止

- 次回は `start-atem.cmd` を開くだけです。IPとキーを再利用します。
- ガイド画面を開いたまま使います。閉じると、このツールで起動した仲介プロセスだけを停止します。PC再起動後は再び起動してください。
- 自動起動・Windowsサービス化は行いません。映像の切り替えも自動実行しません。

IP変更時は停止後、プロジェクトのフォルダーで次を実行します。

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\start-atem.ps1 -ChangeAddress
```

キーを再発行する場合（全操作端末で再入力が必要）:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\start-atem.ps1 -NewKey
```

## OBS・ATEMの環境プロファイル

「接続・同期」で両方のURLを同じプロファイルに設定します。「OBSと同じPCのATEM URLを入力」は候補の入力だけで、ネットワーク変更・接続は行いません。別PCに仲介を置く場合はそのPCのHTTPS URLを指定してください。

キーはATEMタブで入力します。「この端末にキーを記憶する」は任意です。ブラウザ内には暗号化せず保存するため、自分専用の端末だけで使い、端末ロックを設定してください。解除やURL変更で保存キーを削除します。保存を選ばなければ今回の接続だけに使います。

プロファイル変更・取り込みはATEMを切断します。新しい接続先へ勝手に接続しません。旧OBSプロファイルも使え、旧形式のATEM URLは既存のアクティブ環境だけへ移行します。

## 新しいスマホ・PCへの引き継ぎ

### アカウントなしで渡す

1. 設定済みの端末で「接続・同期」→「別端末への引き継ぎ・バックアップ」を開きます。
2. 通常JSONにはURL・プロファイル・操作設定が入り、OBSパスワード・ATEMキーは入りません。
3. 保存済みの認証情報も渡す場合は、12文字以上の強いパスフレーズを入力し「暗号化ファイルで渡す」を選びます。ファイル全体をAES-GCMで保護します。未保存のキーは含まれません。
4. ファイルを安全な方法で別端末へ渡します。パスフレーズは別の経路で伝えてください。キー入りのURL・QRは作りません。
5. 新端末で同じ画面を開き、パスフレーズを入力して「設定ファイルを取り込む」を選びます。現在の環境一覧全体を置き換える確認が出るので、必要なら先に書き出してください。
6. Tailscaleと仲介PCの起動を確認し、OBS・ATEMへそれぞれ接続します。

暗号化ファイルの取り込み後、復号された認証情報はブラウザへ保存されます。共用端末には使わないでください。ファイルとパスフレーズを両方持つ人は復元できます。パスフレーズを忘れると復元できません。

### クラウド同期

既存のSupabase同期を使えます。OBS・ATEMのURLと操作設定は通常設定として同期します。OBSパスワードとATEMキーの暗号化同期は個別に選択します。ATEMキーを復元する端末でも「保存したATEMキーも暗号化して同期・復元する」を有効にしてから取り込んでください。同期用パスフレーズは端末内だけで使用し、実機状態やセッションはSupabaseへ送りません。

## 保存と安全上の境界

- Windows: `%LOCALAPPDATA%\OBSRemotePanel\ATEM\config.clixml`。キーはWindows DPAPIで暗号化し、同じPC・同じWindowsユーザーだけで復号できます。アクセス権は本人とSYSTEMに限定します。別PCへこのファイルをコピーしても使えません。
- ブラウザ: 任意保存のATEMキーは専用のローカル保存領域に分離します。古いアプリが通常設定を書き出してもキーが混ざらないための対策で、暗号化ではありません。Windows DPAPIとは異なり、同一オリジンのコードや端末へのアクセスに対する完全な保護ではありません。
- 仲介PCの交代: 新PCで初期設定し、操作端末のURLとキーを更新します。PC同士のIP重複に注意してください。
- 操作端末だけの追加: 仲介PCの再設定は不要です。
- キー再発行は全体の更新です。端末別の失効・期限付きペアリングは未実装です。

既存OBSセットアップ、OBS認証、Windowsネットワーク設定は変更しません。Funnel・ポート開放・Serve全体のリセットは使いません。追加したATEM用パスだけを解除するには次を使います。

```powershell
tailscale serve --https=443 --set-path=/atem off
```
