# 機材PCと操作端末を分ける新方式

## 設計の評価と今回の範囲

機材PCではOBS・ATEMと仲介ツールだけを動かし、Remote Panelは別PC・スマホで開きます。
短いコードだけの登録は接続先発見用サーバーが必要になるため、今回はアカウントなしの「QR／登録リンク＋機材PCでの承認」にしました。
旧来の直接接続と起動ツールは残し、新方式を選んだ環境だけが変更されます。

| 候補 | 評価 |
| --- | --- |
| 共通パスワードをQRで配布 | 入力は減るが、端末1台だけの解除が難しいため今回は採用しない |
| ユーザーID・パスワードの新規アカウント | ログイン・復旧・アカウント管理が増える。個人利用の現段階では保留 |
| QR／登録リンク＋機材PCの承認 | 新しいアカウント不要。端末別に操作許可を取り消せるため今回採用 |

初回だけ機材PC側で承認が必要になる点は残ります。承認を省略して接続の手軽さを優先する設計にはしていません。

新方式のOBSパスワードは機材PCから出ません。操作端末には固有の認証情報を発行し、機材PC側ではそのハッシュだけを保存します。
OBSとATEMの操作、操作端末の登録、操作設定の共有を分離しました。機材PCを止めると、両機器への新方式の遠隔操作が止まります。

## 最初の設定（機材PCで一度だけ）

1. Node.js 20.19以上とTailscaleを用意してログインします。
2. OBS WebSocketの認証を有効にします。ATEMのLAN・IPは手動で設定してください。
3. 最新プロジェクトの `start-panel.cmd` をダブルクリックします。
4. 機材PC名、OBSを使うか、OBSのポートとパスワード、ATEMを使う場合はLAN IPを入力します。
5. 新しいTailscale Serveパス `/panel` の追加内容を確認して承認します。既存 `/`（OBS直接接続）、`/atem` は変更しません。
6. 機材PC用の画面が開きます。ここでRemote PanelのWeb画面を開く必要はありません。

OBSだけ／ATEMだけ／両方に対応します。OBSはこのPCの127.0.0.1へ接続します。任意の外部OBS URLへの中継には使えません。
通常は管理者権限を要求しません。既存設定競合やFunnelがある場合は、何も上書きせず停止します。

## 別PC・スマホを追加する

1. 操作端末も同じTailscaleネットワークへ参加し、機材PCへ通信できるようにします。
2. 機材PCの「端末を追加」を押します。QRと登録リンクが表示されます。
3. スマホはQRを読みます。別PCは登録リンクを開くか、Remote Panelの「接続・同期」にリンクを貼ります。
4. 操作端末名を入力し「この端末の登録を申請」を押します。勝手に申請・接続することはありません。
5. 機材PCの承認待ちに同じ端末名と確認番号が出るので、操作端末と照合して「許可」します。
6. 操作端末に環境プロファイルが追加されます。OBSは上部の接続、ATEMはATEMタブの接続ボタンで使います。

招待は2分間・1回限り、申請も2分以内の承認が必要です。公開前のブランチでは、QRから開く公開Web画面がまだ対応していない場合があります。PRの公開完了後に実端末で確認してください。
登録リンクを他人やこのチャットへ送らないでください。URLには機材パスワードや長期の端末キーは入りませんが、短期の登録情報が含まれます。
QRは機材PC内で生成し、外部QRサービスへ送信しません。リンクの登録情報はURLフラグメントに入り、Web画面が読み込むと履歴上のURLから除去します。

## 毎回使うとき

機材PCでは `start-panel.cmd` を起動するだけです。操作端末は保存した環境を選び、接続します。
機材PCの画面の×は最小化です。停止は「機材への仲介を終了」で行います。Windows再起動後の自動起動・サービス化は含みません。
一時的なOBS切断は再接続しますが、操作命令は再送しません。OBS操作がタイムアウトすると新しい書き込みを停止するため、本体を確認してから仲介を再起動します。

## 操作設定の引き継ぎ（ファイル不要）

設定済みの操作PCで「接続・同期」→「操作設定を機材PCへ保存」を押します。
別の登録済み端末で「操作設定を取り込む」を押すと、同じボタン配置・お気に入り・シーン表示設定等を利用できます。
取り込み・上書きには確認を挟みます。機材PCごとに共有設定は1セットです。同時更新はrevisionで検出します。
共有するのは操作設定だけで、接続URL・パスワード・認証情報・端末の操作許可は渡しません。
旧来のJSON／暗号化ファイル／クラウド同期も残りますが、端末専用の登録情報はそれらに含みません。

## 登録解除と機材設定の変更

機材PCの登録済み一覧から、対象端末を選び「登録解除」します。その後のOBS／ATEMへの要求を拒否します。
すでに機器へ送信済みの操作は取り消せません。ほかの登録端末は影響を受けません。
ブラウザの「登録情報を忘れる」は、そのブラウザの切断とローカル情報削除です。紛失端末は必ず機材PCから解除してください。

機材の設定変更は仲介を停止後、プロジェクト内で次を実行します。端末一覧は保持します。

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\start-panel.ps1 -Reconfigure
```

## 保存と安全上の境界

- 機材PCの設定は `%LOCALAPPDATA%\OBSRemotePanel\Panel\config.clixml`。OBSパスワードをWindows DPAPIで暗号化し、本人とSYSTEMだけにフォルダーアクセスを許可します。
- 同じ場所の `devices.json` は端末名・ID・認証情報のハッシュ、`operations.json` は共有操作設定です。機材の状態やWebSocketセッションは保存しません。
- 操作端末の専用認証情報は、ブラウザの独立したローカル領域に保存します。暗号化されていないため、自分専用の端末と画面ロックを使用してください。ブラウザ内の悪意ある同一オリジンコードや端末侵害への完全な防御ではありません。
- 操作端末は全操作権限を持ちます。閲覧専用・細かい権限分けは未対応です。
- 管理用APIは別の127.0.0.1:8790で、起動ごとに生成した専用キーを要求します。Tailscale経由の公開対象にはしません。
- `/panel` は127.0.0.1:8789へ中継します。許可Originを固定し、承認済み端末の認証を毎回確認します。
- OBSへの転送はRemote Panelで使う要求だけに限定します。入力設定・配信サービス設定・Vendor/Batch要求などは受け付けません。イベントも必要な項目だけに絞ります。
- 既存の直接接続URLは残っています。その認証情報を知る端末は新方式の登録解除とは別に接続できます。旧方式を廃止する場合は別途計画して停止・キー変更してください。自動削除はしません。

新方式だけのServe解除:

```powershell
tailscale serve --https=443 --set-path=/panel off
```

Funnel、ポート開放、認証無効化、Serve全体のリセットは行いません。現在動いている旧仲介も自動停止しません。

## 確認範囲

自動テストは承認前拒否、期限切れ、再使用拒否、端末失効、ハッシュ保存、管理API分離、OBS許可要求とイベント、ATEM転送、設定共有の秘密情報除外と競合、WindowsのDPAPI保存を扱います。
開発時は `npm ci` に加えて `npm ci --prefix bridge --ignore-scripts` で仲介側の依存を復元してから `npm run check` を実行します。PR検証もこの手順で、Secrets・Pages書き込み権限は渡しません。
新方式での実OBS・ATEM接続、Windows GUIの操作、スマホのQR読み取り、ネットワーク断からの復旧は、非本番の時間に追加確認してください。

依存追加は機材PC側のみです。[obs-websocket-js](https://github.com/obs-websocket-community-projects/obs-websocket-js)をOBS仲介に、[node-qrcode](https://github.com/soldair/node-qrcode)をローカルQR生成に使います。
